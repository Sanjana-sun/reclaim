# Overturn — MVP scope & 90-day plan

## MVP thesis
Ship the smallest thing that (a) produces a genuinely good appeal a patient will sign and
send, (b) captures the win/loss outcome so the data flywheel starts turning, and (c) is
compliant by construction. Everything else waits.

## v1 feature scope (in)
1. **Intake** — insurer, plan type (commercial / ACA / Medicare Advantage / employer/ERISA),
   denial reason (structured dropdown of the top ~12 CARC/denial categories), service/treatment,
   drug name (if applicable), free-text description, upload of the denial letter (PDF/photo).
2. **Appeal generator** — LLM produces a structured internal-appeal letter:
   - correct appeal type + deadline for the plan type,
   - argument mapped to the denial reason,
   - a **medical-necessity section that references the patient's treating physician's
     letter/records** (clinician-in-the-loop; the AI does not assert clinical opinion itself),
   - citations to the plan's own policy language / published clinical guidelines where available.
3. **Review & edit** — patient edits, then downloads a PDF and/or copy-paste text. **Patient
   signs and submits** (we do not submit on their behalf in v1).
4. **Deadline tracker** — reminder for the appeal window and expected decision date.
5. **Outcome capture** — "Did it get overturned?" follow-up → the win/loss dataset.
6. **Compliance UX** — AI-use disclosure, "not legal/medical advice" disclaimers, no
   outcome guarantees, honest efficacy copy.

## Explicitly out (v1)
Auto-submission to insurers; medical-bill negotiation (Phase 2); pharma/provider portals;
payments beyond a simple per-appeal charge or waitlist; native mobile app; EHR integrations.

## Tech stack (bias to speed + compliance)
- **Frontend**: Next.js + TypeScript + Tailwind (SSR, fast to ship, easy hosting).
- **Backend**: Next.js API routes / a thin Node service; Postgres (managed, encrypted at rest).
- **LLM**: Claude (Opus for drafting quality, Haiku for cheap classification) via the Anthropic API.
- **Docs**: server-side PDF render; PDF/image intake via a document parser + OCR.
- **Auth**: email magic-link (minimize credentials); per-user data isolation.
- **Infra/compliance**: encryption in transit + at rest; access logging; no third-party
  ad-tech/trackers on any page touching health data; signed sub-processor DPAs; breach-notification runbook.
- **Data flywheel**: store (denial reason, insurer, plan type, appeal text hash, outcome) —
  never train on raw PHI; work from de-identified features.

## Architecture (guardrails as structure, not copy)
- A **classifier** step (Haiku) maps the denial to a reason category + plan type → selects the
  correct appeal template + deadline logic. Deterministic rules own deadlines, not the LLM.
- A **drafting** step (Opus) fills the template; a **medical-necessity module** only *formats
  and references* clinician-provided evidence — a hard boundary in the prompt + UI (no
  clinical assertions generated by the model).
- A **safety linter** post-processes output to strip guarantees, add disclaimers, and flag
  anything reading as legal/medical advice.
- Patient-signs-and-submits is enforced by product flow (no send API in v1).

## 90-day plan
**Weeks 1–2 — Validate + foundations.** Run the validation test (see validation-plan.md).
Stand up repo, auth, DB, Anthropic API, hosting. Draft the top-3 denial-reason templates with
a health-insurance-savvy advisor.

**Weeks 3–5 — Core generator.** Intake → classify → draft → review/edit → PDF. Ship the
safety linter and all compliance copy. Manual QA of letters against real denial examples.

**Weeks 6–8 — Private beta.** 25–50 real users from the validation waitlist (start with one
chronic-condition community, e.g. a GLP-1 or specialty-drug group). Instrument everything.
Add deadline tracker + outcome capture. Iterate templates on real letters.

**Weeks 9–10 — Monetize v1.** Per-appeal charge (or cheap subscription); measure conversion +
willingness to pay. Confirm CROA-safe fee timing.

**Weeks 11–12 — Prove the loop + prep B2B2C.** Publish real (substantiated) win-rate data.
Ship the "I got $X reversed" share flow + 3 SEO landing pages for the beachhead condition.
Package early outcome data into a one-pager for the first pharma/clinic conversations.

## v1 success metrics
- ≥40% of started intakes reach a downloaded appeal.
- Self-reported overturn rate on submitted appeals (target: beat the ~44% baseline).
- ≥10% free→paid conversion in the beachhead cohort.
- 50+ outcomes captured (the dataset has started compounding).
